# Amazon Clone — 8x Engineering Assignment

An Amazon.com-inspired shopping experience, rebuilt as a frontend product assignment. Amazon is used as a reference for familiar patterns, not a blueprint: the goal was a focused, working journey from homepage to order confirmation, with deliberate product and UX decisions rather than a pixel-perfect copy.

## What I Built

- A responsive Amazon-inspired storefront with a focused header (logo, search, cart)
- Homepage discovery: categories, today's deals and best sellers drawn from real catalogue data
- Search with typeahead suggestions from the local catalogue
- Search, filter and sort state held entirely in the URL
- Product detail pages with variants (colour, size, capacity, format) and an image gallery
- A persistent shopping cart with quantity limits, remove + undo, and stock checks
- A single-page checkout: address, delivery speed, demo payment, review
- A demo order confirmation page
- Layouts designed for phone, tablet and desktop
- Loading, error, empty and invalid-data states on every page

## Product Decisions

The project deliberately does not reproduce every Amazon feature. Each feature had to improve the core journey (home → search → product → cart → checkout → confirmation) enough to justify building it.

All 46 decisions are recorded in [`docs/PRODUCT-DECISIONS.md`](docs/PRODUCT-DECISIONS.md). Each one states Amazon's behaviour, what changed, why, the user benefit and the tradeoff. Examples:

- **A focused journey:** a header with three jobs (logo, search, cart) instead of nine controls; a homepage with four modules instead of twenty.
- **Less Amazon-style clutter:** no sponsored placements, Prime upsells, AI suggestions, gift options or "compare with similar items".
- **No auto-playing or arrow carousels:** a static hero; swipe rows on phones and full grids on desktop.
- **Honest states:** empty and error states explain what happened and offer a way forward, never filler products.
- **URL-driven search:** query, filters and sort live in the URL, so refresh, Back/Forward and shared links all work.
- **Impossible purchases are blocked:** cart lines that exceed stock, are sold out or no longer exist are explained, never silently changed or let through to checkout.
- **Checkout is clearly demo-only:** no card-number fields at all, and every relevant screen says no payment is taken.
- **Mobile by design:** phone layouts are built for thumbs (full-width search, swipe rows, a filter drawer, and sticky purchase/checkout bars) rather than a shrunken desktop.

## Tech Stack

- React 19 + TypeScript
- Vite
- React Router
- Tailwind CSS 4 (design tokens in `src/index.css`)
- Vitest for unit tests
- Inter, self-hosted via `@fontsource-variable/inter`

The catalogue is local data (38 products across 5 categories, with fictional brands) served through a small async API layer that simulates latency. There is no production backend. Product images are SVGs generated by `scripts/generate-images.ts`.

## Key Features

- **Homepage:** hero with popular searches, shop by category, today's deals and best sellers
- **Search:** typeahead with keyboard support, tolerant matching, and a "no results" page with suggestions
- **Filters and sorting:** category, price, rating and deals; five sort orders; a filter drawer on mobile
- **Product variants:** every option resolves to a real in-stock variant; the selection is kept in the URL
- **Product image gallery:** thumbnails on desktop, swipe on touch
- **Cart:** saved in `localStorage` and synced across tabs; line totals; stock limits; remove with undo
- **Checkout:** US address form with validation and autofill, Standard or Express delivery, demo payment
- **Order confirmation:** order number, arrival date, address, items and totals
- **Responsive design:** 360 px to 1440 px+
- **Accessibility:** keyboard support, visible focus, labelled controls, live announcements
- **Loading, error and empty states:** testable on demand with `?simulate=slow`, `?simulate=error` and `?simulate=order-error`

## Project Structure

```
src/
  pages/        Route-level pages: Home, Search, Product, Cart, Checkout, Order confirmation, 404
  components/   UI by area: layout, home, search, product, cart, checkout, and shared ui primitives
  data/         Typed local catalogue, selectors and homepage curation
  api/          Async catalogue and simulated order API (the seam for a real backend)
  state/        Cart store and checkout draft (pure reducers/validators with unit tests)
  lib/          Search, suggestions, variants, delivery rules, money and route helpers
public/images/  Generated product artwork
scripts/        Product image generator
docs/           PRODUCT-DECISIONS.md
recon/          Amazon.com reconnaissance notes and screenshots used as reference
.agent-logs/    Agent interaction capture logs
```

## Getting Started

Requires Node.js and npm.

```bash
npm install
npm run dev          # start the dev server
npm run build        # typecheck and production build
npm run preview      # serve the production build
npm run typecheck    # TypeScript only
npm test             # unit tests (Vitest)
npm run images       # regenerate product artwork
```

## Responsive & Accessibility

The final QA pass covered every major page (homepage, search, product, cart, checkout, confirmation, 404) at **360, 390, 768, 1024 and 1440 px**, checking for horizontal overflow, clipped text, overlapping controls and minimum text size.

Accessibility checks covered:
- keyboard navigation through the whole journey
- a visible focus ring on every Tab stop, and no keyboard traps
- a working skip link
- accessible names and labels on all buttons, links and form controls
- one h1 per page and no skipped heading levels
- alt text on images
- focus management after form errors, remove/undo and checkout failures
- Escape closing search suggestions and the mobile filter drawer

These were automated and keyboard checks in an emulated browser, not a full screen-reader audit or testing on physical devices.

## Demo / Scope Limitations

- No real payment processing; payment options are demo-only
- No real orders are placed and nothing ships
- No user accounts and no production backend
- Orders are kept in the browser tab they were placed in; there is no order history
- Stock does not decrease after an order (the catalogue is static)
- The delivery address is not kept between visits (it is held for the current tab only)
- No tax or promo-code system
- US-only delivery, prices in USD, and delivery dates based on the device clock
- Hosting needs an SPA fallback (all routes served `index.html`) so deep links such as `/dp/...` work on refresh

## Agent Logs

`.agent-logs/` contains the agent interaction/capture logs required as part of the assignment. They are kept exactly as generated.

## Assignment Safety

Checkout and payment are simulated. Placing an order runs a local, simulated API call; no payment details are collected and no real transaction is performed.

## Final Notes

This was built as a focused frontend product exercise inspired by Amazon. The emphasis was on making deliberate product and UX decisions about what to keep, simplify, remove or improve, and on implementing them carefully.
